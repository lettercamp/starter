Saving a draft while offline is straightforward enough. The browser can store the document locally and send it later.

The difficult case starts when “later” arrives. You wrote on the train, opened the same draft on your laptop, and made a different change there. Now your phone reconnects. Which version should win?

For Good Product's first release, our answer is: neither version gets to win silently.

## Separate the local save from the server save

The editor writes a recovery copy to IndexedDB as you work. That protects against a refresh or a dropped connection in ordinary conditions, but it is not a backup service: clearing browser data or losing the device can still remove local drafts.

We show two different states. **Saved on this device** means the local write completed. **Synced** means the server accepted that revision. A single reassuring “Saved” label would hide an important distinction.

## Every write has a starting point

A save request includes the revision the editor started from. The server only accepts the write if that revision is still current.

If another device has already changed the draft, the server rejects the stale write and returns the current revision. We preserve the local text and show both versions. The author can compare them and choose what to keep.

This is less seamless than automatic merging. It is also easier to explain, test, and trust for the relatively short updates people write in Good Product.

## Retries should not create new revisions

A connection can fail after the server saves a draft but before the browser receives the response. Retrying that request should return the original result, not create another version.

Each write carries a unique request ID. The server remembers accepted IDs long enough to recognize retries and return the revision already created.

## Why we stopped short of live collaboration

We are not presenting this as a multiplayer editor. Two people cannot safely type into the same draft and expect their changes to merge in real time.

For 1.0, a draft has one author, local recovery, and explicit conflict handling across devices. That boundary lets us protect the text first. We can expand the collaboration model when we can make its behavior equally clear.
